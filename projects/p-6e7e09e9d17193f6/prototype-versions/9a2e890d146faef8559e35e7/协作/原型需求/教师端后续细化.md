# 教师端后续细化交接单

> 本分支用于伙伴在已确认框架内继续细化教师桌面端原型与需求，不用于重新定义产品框架。修改完成后提交本分支，由项目负责人评审；未经确认不合并到 `main`。

## 任务信息

- 任务名称：教师桌面端细节优化与需求补全
- 分支：`partner/teacher-polish`
- 负责人：接手伙伴（GitHub 账号由项目负责人授权）
- 基于 `main` 的提交：`cecaadc`
- 交付日期：按项目负责人后续安排

## 原型依据

- 原型项目：`teacher-desktop-prototype/`
- 原型生成器：私有仓库 `ppzhang011-commits/prototype-generator`，源码运行后添加本项目根目录。
- 默认入口：`index.html`；页面与状态以 `.prototype/project.json` 为准。
- 需求与标注：`.prototype/prd.json`；项目事实与待确认边界：`AGENTS.md`、`.prototype/brief.md`。
- 当前版本：教师端 `cecaadc`；原型生成器使用交接时私有仓库 `main` 最新版本。
- 当前“基本设置”重点标注：时间设置、数量设置、活动开展规则、二次编辑与保存影响。编号和正文以工作台实时显示为准，不凭截图重建。

## 已确定，必须保持

- 教师端一级页面仍为学生社团主页、分析报告、社团审核、社团学分审核和配置；详情与审核工作台属于二级页面。
- 学生主导、学校必要治理、过程事实优先等产品原则，以根目录 `AGENTS.md` 为事实基线。
- 已确认业务对象、术语、流程和页面决定不得因视觉细化而改写；未确认内容必须标为建议或待确认。
- 页面需求和序号标注保存在本项目 `.prototype/`，不得只改页面代码而遗漏需求资产。
- 原型生成器是独立工具仓库，不复制进本项目，也不在本分支修改生成器源码。

## 本次请细化

- 仅处理项目负责人明确指派的页面、状态和业务项；没有具体范围时先列出准备修改与撰写的清单，等待确认。
- 结合页面内容选择信息、交互、校验、业务逻辑、异常说明、规则表或状态机，不机械补齐固定模板。
- 跨时间、数量、规则等分组共同适用的逻辑单独写通用标注；移动通用说明时保留各分组自己的字段与规则。
- 页面代码、交互结果、PRD 正文、序号标注和 `.prototype/brief.md` 保持一致。
- 如修改会影响既有业务记录，先说明影响范围、新旧数据边界和处理选项，确认后再落为正式规则。

## 边界与待确认

- 可以调整：已指派页面内的布局、层级、文案、演示数据、交互细节，以及对应未确认需求的整理方式。
- 不得改变：一级信息架构、核心角色、已确认业务链路、权限原则、项目身份、发布身份，以及其他页面的既有需求和标注。
- 不得直接向 `main` 推送或自行合并；不得发布、取消发布、删除远端目录或修改 GitHub 配置，除非项目负责人对该动作明确授权。
- 待确认问题以 `AGENTS.md` 第 7 节及各页面 `.prototype/brief.md` 为准；原型中的示例值不能自动升级为业务规则。

## 验收

- `npm run build` 与 `npm run test:sites` 通过。
- `.prototype/project.json`、`prd.json`、`changes.json` 的 `revision` 与 `projectId` 一致，页面文件、标注和 `prd-assets/` 无断链。
- 仅提交任务范围内的源码、原型元数据和必要附件，不提交 `node_modules/`、`dist/`、本机配置、密钥或缓存。
- 更新 `.prototype/brief.md`，记录本轮已确认规则、明确否定方案和仍待确认事项。
- 回交时说明修改页面、需求标注、验证结果、遗留问题和提交编号，等待项目负责人评审后再决定是否合并。
