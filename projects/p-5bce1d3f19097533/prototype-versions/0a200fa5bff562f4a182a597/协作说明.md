# 学生端原型协作说明

本仓库同时保存学生端原型代码、图片资源和原型生成器标注。伙伴可以使用任意本地 AI 工具，不要求使用 Codex。

## 伙伴首次操作

1. 从 GitHub 下载或克隆本仓库。
2. 切换到 `partner/student-polish` 分支，不直接修改 `main`。
3. 使用自己的 AI 工具打开整个 `student-desktop-prototype` 文件夹。
4. 首次运行执行 `npm install`，预览执行 `npm run dev`。

## 原型生成器

1. 启动原型生成器。
2. 在首页点击“添加本地项目”。
3. 选择完整的 `student-desktop-prototype` 文件夹，不要只选择 `src` 或 `dist`。
4. 在本地 AI 工具中说明需要调整的页面、交互和需求，由 AI 工具修改项目中的真实源码。
5. 继续在 AI 工具中整理页面需求和标注，并让 AI 调用原型生成器的项目接入／PRD 导入能力，将需求与标注写入当前原型项目。
6. 打开原型生成器工作台，检查原型、PRD 和序号标注；可以在工作台中继续修改标注内容、位置和对应元素。
7. 如检查后还需修改页面，回到 AI 工具继续调整源码，再刷新原型生成器复核，直到原型与标注一致。
8. PRD、标注及修改任务会保存在仓库中的 `.prototype/` 文件夹。

> 工作台只服务静态 HTML，读取的是 `npm run build` 生成的 `pages/` 目录，不会编译 `src/`。修改源码后重新执行 `npm run build` 再刷新工作台；根目录 `index.html` 仍是 `npm run dev` 的入口，已在工作台中移入回收站。

左侧目录对应 `pages/` 下的 HTML：首页是 `pages/index.html`，社团广场／社团申报／我管理的／我报名的／社团报告分别是 `pages/entries/plaza.html`、`applications.html`、`manage.html`、`mine.html`、`report.html`；「社团详情」「社团风采」是 `entries/club-detail.html`、`entries/club-gallery.html`，挂在「社团广场」下作为子级；「申报表单」「我的草稿」是 `entries/declaration-form.html`、`entries/drafts.html`，挂在「社团申报」下作为子级；「活动瞬间」是 `entries/moment-wall.html`，挂在「我报名的」下作为子级。新增独立页面时，在 `entries/` 新建 HTML（用 `window.__PROTO_PAGE__` 指定应用内页面），并在 `vite.config.mjs` 的 `rollupOptions.input` 中注册，执行 `npm run build` 后会自动出现在目录中。在左侧目录拖动页面，或选中后按 Alt + 方向键，即可把它移入某个页面成为子级目录。

不要单独复制原型生成器的数据库，也不要删除或重新生成 `.prototype/project.json`。代码修改与 `.prototype/` 标注必须一起提交。

## 每次交付

1. 确认原型可以正常运行。
2. 执行 `npm run build`。
3. 提交并上传当前分支的全部改动，包括 `.prototype/`。
4. 在 GitHub 创建从 `partner/student-polish` 合并到 `main` 的 Pull Request，通知项目维护人验收。

## 最终交付

维护人将伙伴分支合并进 `main` 后，在原型生成器中重新打开学生端项目，检查代码和标注，再导出“研发版”。研发版是最终可评审的一份交付包，包含原型、页面导航、PRD 和序号标注。
